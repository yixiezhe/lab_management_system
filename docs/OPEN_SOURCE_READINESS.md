# 开源候选状态（2026-09-24）

本仓库目前保持私有，尚未正式开源。主项目许可证与发布权利待所有者确认。

## 已完成的准备

- 原 GitHub 地址保留不变，用于开源候选代码。
- 日常开发与原历史另存于独立私有仓库，不作为公开版本发布。
- main 与准备分支从脱敏快照建立独立根提交，不继承原始提交历史。
- 当前对外候选不包含 .env、真实业务数据库、附件、导出账表、照片、机构标识、模型权重或运行环境本体。
- 凭据由环境变量提供；成员名单采用虚构示例；演示数据为手工编写的虚构配置。
- 未核实再分发权利的 Guacamole 自定义 JAR、端侧脚本、部署 SQL 不随候选发布。
- 保留前后端业务代码、迁移、Agent/LangGraph/RAG 实现与相关文档。
- 提供隔离 CI：容器构建、空库迁移、Django 检查与测试、合成数据登录冒烟检查。
- CI 使用 GitHub 托管临时环境和随机临时凭据，不接入现有服务或真实模型 API。
- CI 配置已提供不等于运行通过；实际结果以对应提交的 Actions 为准。

## 本次操作边界

不修改本地和服务器应用源码、未提交改动、生产数据库、运行容器或现有凭据。
历史重建仅针对 GitHub 开源候选仓库；不重置本地开发分支。
新增加的文件均不超过 500 行，未为此重构原有大文件。

## 正式公开前仍须完成

1. 所有者确认代码、流程文档及资源的公开权利，明确选择主项目许可证。
2. 撤销或轮换旧历史中仍有效的凭据；此次不代改生产密码或加密密钥。
3. 检查旧提交的直接链接、GitHub 缓存、其他克隆与引用；必要时联系 GitHub Support。
4. 防止旧本地/服务器副本重新推送旧历史。服务器 Git 地址仍需所有者另行确认如何处理。
5. 检查最新 CI 结果并处理失败，再执行完整业务权限回归和依赖漏洞审查。
6. 评估第三方依赖与模型许可，确认未随代码携带未获授权的资料。
7. 所有者在实际公开时再次确认仓库可见性变更。

## 历史清理不是密码失效

重写分支会改变可达历史，不保证 GitHub 立即物理删除旧 Git 对象、
提交页面、缓存或其他副本。旧历史的私有备份仍然含有敏感信息，不能公开。
不要以“当前分支已脱敏”为理由跳过有效凭据轮换。

依据：[GitHub 敏感数据清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。
